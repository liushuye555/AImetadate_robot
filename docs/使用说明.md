# 使用说明

## 1. 项目位置

```text
项目根目录
```

项目代码、配置、启动脚本、数据库、日志、本地页面均集中在该文件夹。

接入框架可在设置中选择通用 OneBot v11、NapCat、LLBot、SnowLuma、Lagrange.OneBot；实际端点须提供 OneBot v11 正向 WebSocket。配置和能力检查见 [框架接入兼容性](框架接入兼容性.md)。外部模式不自动启动 NapCat。

## 2. 前置条件

- Windows 10/11。
- Python 3.11+，当前由 `uv` 管理。
- 可用的 OneBot v11 正向 WebSocket 服务。使用项目内 NapCat 时目录为：

```text
runtime\NapCat.Shell.Windows.Node
```

- 所选框架已登录 QQ，并启用 OneBot v11 正向 WebSocket。以下为默认示例，实际地址在设置中填写：

```text
ws://127.0.0.1:3001
```

- 使用项目内 NapCat 时，默认 WebUI 为下列地址；其他框架按实际管理地址填写，也可留空：

```text
http://127.0.0.1:6099
```

## 3. 安装依赖

```bash
# 在你保存项目的根目录执行
uv sync --extra dev
```

首次部署时：

```bash
cp config.example.yaml config.yaml
cp .env.example .env
```

不要把 `.env` 内容发到聊天、提交到公开仓库或写入文档。

## 4. 配置

主配置：

```text
config.yaml
```

关键配置说明：

```yaml
onebot:
  ws_url: "ws://127.0.0.1:3001"

listen:
  blocked_groups:
    - "不采集的群号"

reply:
  require_at_in_group: true
  allow_group_admins: true
  whitelist_users:
    - "允许私聊和触发回复的QQ号"
  whitelist_groups: []

storage:
  data_dir: "data"

startup_history:
  enabled: true
  mode: blacklist
  all: true
  max_pages: 200
  count: 50

ai_context:
  enabled: true
  provider: ds_v4_flash
  scopes: all_groups
  chunk_size: 200
  auto_interval_minutes: 15
  min_new_messages: 300
```

DeepSeek 配置放在 `.env`：

```text
DS_V4_FLASH_BASE_URL
DS_V4_FLASH_API_KEY
DS_V4_FLASH_MODEL
```

## 5. 启动与停止

### 后台启动接入服务与 bot

推荐先安装托盘快捷方式：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\scripts\windows\install-tray-shortcut.ps1"
```

打开桌面或开始菜单中的“QQ OneBot Bot”。概览展示所选接入框架、QQ 登录、OneBot 和 bot 的状态。框架管理页读取设置中的地址，外部框架需自行运行；管理器负责启停 bot。用户主动停止后不会自动恢复。

NapCat 默认使用 `runtime/NapCat.Shell.Windows.Node`。`launcher.config.ps1` 仅用于覆盖默认位置，不进入 Git。

不使用托盘时仍可直接运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\scripts\windows\start-qq-onebot-whitelist-hidden.ps1"
```

### 前台调试 bot

```bash
# 在你保存项目的根目录执行
uv run python -m qq_onebot_whitelist.onebot --config config.yaml
```

### 停止

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\scripts\windows\stop-qq-onebot-whitelist-hidden.ps1"
```

停止操作会写入手动停止标记，避免自动恢复竞态；外部接入框架不由项目停止。重新主动启动时该标记会清理。

查看真实运行状态：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\scripts\windows\get-qq-onebot-status.ps1"
```

代码或 bot 配置变更后的重启：

```powershell
.\scripts\windows\stop-qq-onebot-whitelist-hidden.ps1
.\scripts\windows\start-qq-onebot-whitelist-hidden.ps1
.\scripts\windows\get-qq-onebot-status.ps1
```

## 6. QQ 命令

命令里的 `/` 可以省略。

### 私聊白名单用户

私聊默认查询全局数据：

```text
帮助
资源
链接
图片信息
最近总结
最近总结 200
刷新分类
```

### 图片收藏与损坏图片修复（仅私聊）

聊天记录图片不会自动收藏。先在 QQ 中**回复目标合并聊天记录**，再发送以下指令：

```text
保存图片
保存图片 分类名
```

- 不填写分类名时，默认保存到 `未分类` 文件夹。
- 只能在私聊中使用，且必须是对合并聊天记录的回复；直接发送普通消息、群聊中发送或没有回复对象都会返回用法提示。
- 支持嵌套合并聊天记录，最多展开 16 层；重复的合并记录 ID 会跳过，循环引用不会无限递归。
- 图片按 SHA-256 去重。同一张图片在同一分类重复保存时只保留一份，并回复发现数、新保存数、重复数和失败数。
- 收藏图片在数据库图库的 `06_聊天记录收藏/<分类名>` 分类中浏览；原图仍统一保存在 `data/images/ai/`。图库每页加载 60 张，分类从数据库读取，不再建立分类图片硬链接。旧分类页面会跳转到新的图库。

损坏图片可在私聊中重新下载：

```text
修复图片 53619
修复图片
```

- 带 ID 时只修复指定图片；不带 ID 时扫描已归档但无法完整解码的图片。
- 下载先写入每次独占的临时文件，经过 Pillow 完整校验（含完整载入）后才进入归档；并发下载相同 QQ 链接不会互相覆盖，失败文件会自动清理。
- 已损坏归档若能找到同批次的正常图片，会优先复用正常图片替换；找不到时才尝试原链接。
- 原始 QQ 图片链接失效时不会猜测历史接口，请重新转发原聊天记录后再执行 `保存图片`。

### 群聊

群内默认必须 `@机器人`。群命令只查询当前群，避免泄露其他群信息：

```text
@机器人 帮助
@机器人 链接
@机器人 图片信息
@机器人 最近总结 200
@机器人 刷新分类
```

## 7. 数据与页面

### 数据库

```text
data/bot.db
```

主要表：

- `messages`：消息正文、用户、群、原始事件、去重键。
- `links`：链接及分类信息。
- `files`：模型、压缩包、工作流文件元信息。
- `images`：图片元数据、保存路径、保留原因。
- `ai_context_batches`：图片附近可复用参数、处理游标和 LLM usage。
- `link_metadata`：日报链接的网页标题/描述缓存。
- `daily_reports`：已发送日报。
- `history_cursors`：历史补拉游标。

### 图片目录

```text
data/images/ai/             长期归档，不作为缓存删除
data/images/candidates/     临时候选，可按 TTL 清理
data/tmp/                   下载/解析临时文件
data/cache/gallery-thumbnails/ 按需生成的缩略图缓存
```

### 本地页面

```text
data/view/index.html
```

打开：

```text
从项目根目录运行：`Start-Process ".\data\view\index.html"`
```

包含：

- AI 元数据图片。
- 群友好评图片。
- 无原图元数据图片及其附近可复用参数。
- 候选待观察图片（仅在独立的 `04_候选待观察` 分类页浏览，不计入 `00_全部`）。
- 资源链接。
- 群文件/工作流位置记录。

资源链接按规范化 URL 去重（根路径的 `/` 与无 `/` 视为同一链接），并尝试把已知短链解析到最终地址；未解析的小红书等短链不会显示。最终 URL 会缓存到 `link_metadata`，分类优先参考最终域名和路径，再结合网页标题描述和链接附近上下文：工作流站的工作流页、模型站的模型页会归入对应分类；GitHub 仓库归为工具插件。视频细分为 `音乐视频`、`AI教程视频`（教程、部署、工作流、提示词、节点、实测等）、`AI资讯视频`（模型、ComfyUI、AI 产品更新与发布等）和 `娱乐视频`。Linux DO 等论坛归为 `技术社区`；带中转/额度/倍率等明确语义的 API 站归为 `AI中转服务`；Tensor Art、CivitAI 等站的作品、用户与图片页归为 `AI作品展示`。日报的每条链接都会显示所属分类；纯音乐、音乐视频、娱乐视频和图片类链接不发送日报，但仍保留在资源页面。图片托管页和图片直链不进入资源页，网盘单独归为 `网盘资源`，不会因为整条长消息出现“模型”就把所有链接误分为 AI 模型。群文件不下载，按文件名、大小和类型去重，并记录出现过的群。图片文件按 SHA-256 只保存一份，但每次出现记录仍保留。

## 8. 手动刷新本地页面

```bash
# 在你保存项目的根目录执行
uv run python -m qq_onebot_whitelist.maintenance --project-dir .
```

该操作会更新报告与图库入口，并执行原有图片维护任务。图库本身直接查询数据库：新图片完成入库后，点击“搜索 / 刷新”即可查看，不必等待分类页面重建。日常同步不再生成分类图片或画风工具导入目录的硬链接。历史目录暂时保留，以兼容旧报告里的链接；群知识、术语、总结、群文件与资源链接仍保留各自页面。

图库默认只展示图片，缩略图按原始比例排列，不添加面板边框或固定高度留白。点开后使用全屏深色看图：←/→ 或两侧按钮按当前筛选切换图片（可跨页），Esc、关闭按钮或点击背景关闭；按 I 或点击“信息”展开右侧信息栏。信息栏保留来源、尺寸、发送者、提示词复制和点击用户、群组、来源、分类筛选；提示词按需从原图读取，沿用导出提示词的提取规则。每次从图库打开大图时信息默认收起，连续切图时保留当前信息栏开关。

数据库图库工具栏提供以下组合筛选：

- **分类 / 群组 / 发送者 / 生成工具**：可独立选择并叠加；默认全部归档不包含候选图片，候选在独立分类中查看。
- **尺寸**：横图 / 竖图 / 方图（按宽高比 1.2 判定）。
- **分辨率**：短边下限 512 / 768 / 1024 / 1536 / 2048（挑训练素材常用 ≥1024）。
- **日期**：开始日期与结束日期，按数据库保存的 UTC 日期筛选。
- **搜索**：匹配数据库文本摘录、绑定提示词、已选中的完整参数讨论、QQ 号和记录 ID；不区分大小写，回车立即生效。
- **仅重复内容或同工作流**：相同 SHA-256 或重复工作流签名的图片；不执行视觉相似度合并。
- **排序**：最新、最早、分辨率、文件大小。列表使用按需缓存的缩略图，点击查看原图；混淆还原图默认遮罩。

筛选在数据库端执行，再按内容去重并分页，每页最多 60 张。筛选条件保存在页面网址中，可收藏；使用上一页、下一页浏览更多图片。

### 8.0 图形界面导出（推荐）

bot 运行时会自动开一个仅本机可访问的图库服务（端口默认 3017，`config.yaml` 里 `view_server.port` 可改）：浏览器打开 `http://127.0.0.1:3017/view/`，进入图片库，筛选好后点**导出当前筛选**。默认勾选“仅统计，不写文件”，取消后才复制文件。导出与图库共用查询，包含当前群组、分类等条件，并导出全部匹配图片而非仅当前页。**目标文件夹**填绝对路径（如 `D:\datasets\my-lora`）；留空则存到 `data/export/<目录名>/`。可关闭 caption。命令行仍可显式使用 `--link` 导出硬链接。直接打开本地图库入口会跳转到服务地址，因此机器人或独立图库服务需要正在运行。

## 8.1 导出训练数据集（LoRA 用，命令行）

按用户/来源/尺寸筛选归档图片，导出成 kohya/OneTrainer 可直接使用的目录结构（图片 + 同名 `.txt` 提示词 caption）：

```bash
# 先统计不落盘，看每个用户各有多少张
uv run python -m qq_onebot_whitelist.export_dataset --project-dir . --source StableDiffusion_WebUI --min-side 768 --dry-run

# 导出某个用户的图（caption 从原图元数据提取正向提示词）
uv run python -m qq_onebot_whitelist.export_dataset --project-dir . --user 2310806372 --min-side 768 --out my-lora

# 也可以按类目前缀/来源组合筛
uv run python -m qq_onebot_whitelist.export_dataset --project-dir . --category 01 --source ComfyUI --limit 500
```

行为约定：

- 只导出未合并的有效归档记录；先按筛选条件命中，再按 SHA-256 内容去重（重发/转发只保留一条，他人后来的转发不会顶掉被筛用户自己的记录）。
- 图片默认**复制**到 `data/export/<名字>/`（`--link` 改为硬链接，省空间但训练时别删原图），文件名 `0001_<记录id>_<宽x高>.<ext>`。
- caption 默认开启（`--no-captions` 关闭）：从**原图元数据**重新提取正向提示词（数据库里的 text_excerpt 只有 500 字符截断）——A1111/NovelAI 取参数块正向段；ComfyUI 沿采样器节点的 positive 输入找文本节点，找不到时取剔除 negative 后最长的文本；提取失败的图不写 `.txt`。
- 更多筛选：`--orientation landscape|portrait|square`（中文"横图/竖图/方图"也认）、`--keyword 关键词`（匹配元数据文本/绑定提示词，不区分大小写）、`--since/--until YYYY-MM-DD`、`--exclude-user`、`--min-w/--min-h`，可与用户/来源/类目任意组合。
- 导出目录里 `export_manifest.json`（机读，含按来源/用户/类目统计）和 `README.txt`（人读）总会生成，`--dry-run` 时只写统计不落盘。
- 来源筛选同时接受存储值（`A1111`）和显示名（`StableDiffusion_WebUI`）；NovelAI 隐写验证过的图按 `NovelAI` 筛。
- 训练前建议在视图页面再过一遍"只看重复/同批"（或相似组徽标），视觉近似重复的图手动剔除。

## 9. 日报

日报通过 QQ 私聊发送给白名单用户。文件只显示“文件名 + 群”，链接按价值排序并限制数量，显示清理后的可点击 URL 和网页标题/简介；网页抓取失败时回退到聊天上下文，且不显示来源群。没有新增资源时也会发送“今日无新增资源”。

上下文分析可以避开高价时段。例如：

```yaml
ai_context:
  min_new_messages: 300
  allowed_windows: []
```

消息会持续记录并累计，只有同时满足消息阈值且进入允许时间窗口时才调用 LLM。`allowed_windows: []` 表示全天允许，支持多个窗口和 `"23:00-07:00"` 这种跨午夜窗口。也可通过托盘设置，或白名单用户私聊发送“分析时段 查看/设置/全天”，无需 `/`。

- 默认在本地时间 20:00–21:00 检查。
- 只统计上次日报发送后的新增资源。
- 链接与文件均去重。
- 文件写文件名和群；链接写链接和一句简介。
- 群文件不下载，只保存位置记录。
- 明显快手/抖音营销分享会过滤。
- 内容过长时分段发送。

## 11. 常见问题

### bot 在线但不回复

1. 确认端口：`127.0.0.1:3001`。
2. 确认 QQ 号在 `reply.whitelist_users`。
3. 群聊确认已直接 `@机器人`。
4. 查看 `logs/bot.log` 中的 `reply_send`。
5. 检查 `run/bot.pid` 对应进程是否存在。

仅当 provider 为 napcat、manage_process 为 true 且连接地址是本机时，机器人会在断线重连时尝试恢复项目内 NapCat；两次启动至少间隔 60 秒，正在启动或等待登录的 NapCat 不会重复启动。外部模式与远程端点只重连，不自动拉起本机 NapCat。手动停止后不会自动恢复。NapCat 恢复记录位于 `run/napcat-recovery.json`，详情见 `logs/napcat.log` 与 `logs/bot.log`。

### 本地页面没有更新

运行：

```bash
uv run python -m qq_onebot_whitelist.maintenance --project-dir .
```

### 图片页面打不开

确认机器人已启动且 `view_server.enabled` 未关闭，再打开 `http://127.0.0.1:3017/view/`（自定义端口以配置为准）。Qt 报告页的图片分类直接读取数据库。也可独立启动图库服务：`uv run python -m qq_onebot_whitelist.view_server --project-dir .`。知识、术语和文字报告仍可本地打开，图库需要本地服务。

### 收藏聊天记录中的图片

确认操作顺序是：私聊回复合并聊天记录 → 发送 `保存图片` 或 `保存图片 分类名`。不填分类名就是 `未分类`。嵌套记录最多展开 16 层，循环和重复 ID 会跳过；同分类按 SHA-256 去重。

### 归档图片损坏

私聊发送 `修复图片 图片ID` 修复单张，或发送 `修复图片` 扫描全部损坏归档图。修复会先下载到临时文件并完整校验，校验不通过不会替换原图；QQ 链接失效时需要重新转发原聊天记录。

### DeepSeek 没有消耗

- 自动分析每 15 分钟检查。
- 累计新增消息达到 300 条才触发。
- 没有待关联的无元数据图片时不会调用 AI。
- AI 只提取可照抄的提示词、模型、LoRA、工作流和参数，不总结群聊主题。
- 查看 `ai_context_batches` 和 `logs/bot.log`。
