# 群知识功能使用说明

群知识功能为可选功能，默认关闭。它使用独立的 `knowledge.db` 保存知识索引和分析结果；原有 `bot.db` 消息库不会迁移。启用群知识不会修改现有采集、日报、图片分析等功能的设置。

Qt采集页现支持逐群配置。模型故障切换、独立复核、小文件内容预览与纠错优化也需在具体群内主动开启。使用方法和验证记录见 [群知识2345优化](功能规划/2026-10-13-群知识2345优化.md)。

## 知识与术语分开

知识库收录具体问题、方法、排错经验、实测对比和资源用途；术语表收录词义、缩写、黑话与别名。同一段讨论可以同时产生知识和术语解释，两类结果各自保存、筛选和检索。纯词义解释不应作为知识条目；模型明确标记为术语的输出也不会写入知识列表。

报告提供四个独立入口：

| 页面 | 内容 |
| --- | --- |
| `data/view/knowledge.html` | 知识库，独立筛选精选与待确认知识 |
| `data/view/glossary.html` | 术语表，独立筛选候选、已启用与人工解释 |
| `data/view/knowledge-summary.html` | 群总结与实际覆盖消息数 |
| `data/view/knowledge-files.html` | 群知识文件归档与状态，不替代原有 `files.html` |

每页保留按群筛选、页内搜索和原消息来源。知识纠错和漏收反馈位于知识页。知识与术语已在独立表中保存，无需迁移原始聊天记录。

### 查看已整理的历史资料

管理器的“资料中心 → 群知识”读取正式库 `data/knowledge.db`；“采集 → 群知识”用于配置之后的整理任务。查看已有知识、术语和总结无需开启自动分析。

独立分析目录中的结果不会自动出现在正式库中。完成复核后，可以显式发布指定群的结果：

```powershell
.venv/Scripts/python.exe -m qq_onebot_whitelist.knowledge publish-history --source data/knowledge-optimized-20261015 --group 338431075
```

发布前会逐条核对该群快照与正式消息库的编号、群号、原文及消息身份，再检查结果中的证据编号。发布保留知识分类、质量标记、话题关联、术语解释与总结，并立即更新四个正式资料页。重复发布不会重复入库；正式库中同编号内容已被修改时，会拒绝整批写入并保留修改。原有知识库会先备份到 `data/backups/knowledge-before-publish-*.db`。

此操作不调用 AI，不修改配置、自动整理开关或实时处理进度，也不复制分析目录中的文件字节或本地文件路径。原消息必须已存在于正式消息库，不会通过发布操作导入聊天记录。若需要持续整理新消息，再主动配置并启用目标群的相应功能。

逐群的知识提取与术语学习开关保持独立。关闭术语学习或单独执行知识提取时，不会带入旧术语表作为模型上下文。`analyze --feature extraction` 与 `analyze --feature glossary` 可分别运行单个功能，仍需主动开启对应开关；不指定 `--feature` 时继续一次处理本批已开启的功能。批量处理共用一次模型请求和群预算，但结果分别存储。

## 话题追踪、知识分层与上下文词义

### 先选主题，再看具体情形

群知识页面按“主题 → 具体情形 → 原始讨论与证据”浏览。左侧目录将智谱、GLM 等常见名称归入同一主题，点击主题后再通过“情形类型”查找额度计费、模型接入、账号风控、故障与资源等内容；小屏幕中主题目录自动横向排列。搜索、群筛选、知识／待跟进／归档和分页可以同时使用。

主题只是浏览分类。同一主题中的不同版本、账号、发言者与使用经历保留为独立记录，不会因此合并结论或改变验证状态。模型必须引用本条目的原消息，且引文中实际出现产品名或已知别名，才能归入该主题；对象不足以确认时进入“其他与对象待确认”。原来的 `subject` 指代确认信息独立保留，不会因导航归类就将未知封号对象写成某个平台。

之后的新分析会生成主题标签。要使用当前主供应商补齐已有资料的标签，可显式运行：

```powershell
.venv/Scripts/python.exe -m qq_onebot_whitelist.knowledge organize-subjects --group 338431075 --max-batches 20 --batch-size 10
```

这项维护需已开启目标群的知识提取，受本群当天 AI 预算约束，只使用当前主供应商，不启用备用供应商。每批完整通过原文检查后才发布标签，并先备份知识库；不改写原正文、术语、话题关联或处理进度。已完成的记录会跳过，预算或批次数不足时可继续执行。仅打开页面或更新报告不会触发这项 AI 复核。

知识页按“可复用知识、待解决问题、资源线索、时效信息”分类。默认展示前三类，可切换分类查看服务故障等时效信息；来源时间按原消息的北京时间显示。资源名称、用途、原消息链接和群友反馈分别保存，链接未访问验证时标为未验证线索。

在“采集 → 群知识 → 编辑目标群”中，有两项新增选项，均默认关闭、不会继承默认参数，也不会自动开启依赖功能：

- “追踪话题与后续反馈”：逐群 `extraction.track_topics: true`，还需开启该群知识提取。AI 会判断本批讨论是否为已知问题的新进展；只允许关联本次提供的本群话题，并保留关联理由和历次原文。模型提出已解决时，必须标明原消息验证反馈并提供当前批次原句，否则降为待确认。晚回填旧反馈不会覆盖较新的状态。语义上是否确实同一问题、是否真实解决，仍需模型结合上下文判断。
- “从上下文推断术语”：逐群 `glossary.infer_context: true`，还需开启该群术语学习。模型可依据至少两条不同原文用例提出本群词义或多种解释，展示原文别名和推断理由。上下文推断与含义分歧始终为候选，不自动成为分析采用的已确认释义；人工解释仍优先。关闭推断后保留已有用例，不继续产生推断。

话题追踪开启后，如果提取结果提出关联旧话题，或没有明确说明关联旧话题还是新建，会调用一次专门的话题判断。它必须独立检查是否为同一具体问题，为每项明确选择关联、新建或不收录，并给出依据；同名软件不足以合并不同问题。候选编号越界、缺项、重复决策不会发布结果。这个步骤仍受本群每日预算约束，用量单独记账；已完成主分析会按实际用量结算并缓存，后续判断失败重试可复用。没有旧话题候选时不会额外调用判断。

精选准入同时检查 AI 的内容分类和原文依据。工具自我介绍、价格感受、推广不能仅凭模型评为高价值；公告与服务状态归入时效信息。可复用教程或操作反馈必须提供原文支持的条件、步骤和内容/结果摘录，缺少时保留为候选。价值与验证状态分开：有价值的未实测教程仍是群友说法，不自动变成已验证结果。质量分类、准入原因和引用保存在独立质量表中，重启后仍可查看。

术语页将同一群、同一规范词形的候选集中在一张卡内，每个不同解释保留自己的状态、推断依据和原文证据。词形统一大小写、全半角及空白；释义比较保留技术单位与代码中的大小写和内部空格，因此 `MB/s` 与 `Mb/s` 不会误合并。合并展示不提高置信度，不跨群合并，也不覆盖人工解释。搜索、状态和解释依据筛选同时作用于同一个释义，避免不同解释分别命中造成串漏。

这些修复会用于之后的分析；旧分析结果不会自动消耗 AI 重新计算。重新验证历史应使用独立目录或显式历史重算版本，保留原报告供对照。

话题候选最多取12条，文本快照总量限制8KB；每话题最多补入1条原消息作为辅助上下文，与当前消息共用本批匿名成员标签。全部辅助上下文仍受40条及26KB消息材料边界限制，不计入当前处理数或推进水位。初筛缓存复核使用当时实际展示的话题快照；候选原消息变化导致输入变化时，会形成新的缓存任务。

早期本地复核样例仅补入话题基线与候选词义用例，没有重新调用项目模型接口。2026-10-15 已另建独立快照完成网络攻防群全量真实 AI 回放，见 [全量修复验证](功能规划/2026-10-15-群知识全量修复验证.md)。现有问题缺少解决反馈时仍保持未解决，话题时间线并不代表已发生新的群消息。

## 启用与配置

群知识总开关统一在“采集 → 群知识”中设置；设置页保留默认参数，不再重复提供同一个总开关，避免另一页保存旧值时覆盖已启用状态。

需要同时满足以下条件，功能才会运行：

1. 全局 `knowledge.enabled: true`。
2. `knowledge.groups` 中存在目标群配置，群键为 `group:<群号>`，且该群 `enabled: true`。
3. 对应子功能在该群配置中显式设置为 `enabled: true`。

可独立启用的子功能是 `summary`（总结）、`extraction`（知识提取）、`glossary`（术语学习）、`files`（文件保留）和 `history`（历史回放）。全局缺省为关闭，群列表缺省为空，新群不会自动加入。`defaults` 只提供参数默认值，不能替代群开关或子功能开关。

示例：为一个群开启手动总结、实时知识提取和术语学习。文件保留、历史回放和定期总结仍关闭。

```yaml
knowledge:
  enabled: true
  defaults:
    match_mode: hybrid
    topics: []
    interval_minutes: 15
    min_new_messages: 30
    max_wait_minutes: 60
    batch_size: 100
    max_tokens_per_day: 50000
    summary_max_batches: 5
    files:
      max_file_mb: 512
      budget_gb: 20
  groups:
    "group:123":
      enabled: true
      summary:
        enabled: true
        daily: false
        weekly: false
      extraction:
        enabled: true
        track_topics: false
      glossary:
        enabled: true
        infer_context: false
      files:
        enabled: false
      history:
        enabled: false
```

把 `123` 替换为实际群号。子功能开关需在具体群配置中明确开启；默认参数不能自动打开它们。全局开关、群开关或对应子功能关闭时，该功能不执行。

### 默认参数与计划

实时处理默认每 15 分钟检查一次；至少有 30 条新消息时运行，最长等待 60 分钟后处理；每批最多 100 条。每日初始 token 预算为 50,000。`summary_max_batches` 默认 5，可在全局 defaults 或群配置中设为 1 至 100。超出本次批次或预算时会显示 `partial` 和续跑提示；已完成的水位会保留，后续续跑继续未覆盖部分。调整预算不会重置实时或历史水位。

实时 `extraction`、`glossary`、`files` 各自独立启用。首次开启后，实时游标从该群当前最新消息位置开始，不会自动回填旧历史。历史游标独立于实时游标。历史回放还要求 `history.enabled: true`，并且至少启用 `summary`、`extraction`、`glossary`、`files` 其中一项。

`extraction` 可以直接分析纯文字里的参数交流、技术问答、排错步骤和经验，不要求消息附带图片或文件。图片和附件只是可选证据；文件解析与保留由独立的 `files` 功能控制。分析会把同一批讨论中的不同发言者匿名区分，避免把不同人的说法混为一谈。为补足跨批次对话，每批还会带入最近最多 20 条消息，并沿明确的回复引用最多追溯 4 层；上下文总量最多 40 条。输出必须引用至少一条当前批次消息。没有答案的问题会作为待确认项记录，不会替群友补造解决办法；有复现失败记录的排错经验仍可能有长期价值。

只有在该群 `summary.enabled: true` 时，手动群总结才可用。定期计划 `summary.daily` 和 `summary.weekly` 默认独立关闭；开启后在本地时间 20:00 生成按日期分批的本地摘要，可用 `summary.hour` 调整时间。总结每次最多处理 5 批，可通过 `summary_max_batches` 在 defaults 或该群设置 1 至 100；如果批次或预算不足，结果会标为部分覆盖并保留续跑位置。

`analysis_revision` 默认是 1。增大该值可触发历史结果按新版本重新计算；历史游标与实时游标仍各自维护。只有在确认需要重新分析时才调整版本号。

## AI 与判断边界

“设置 → AI 供应商”保存的接口可供群知识使用。默认跟随全局已选供应商，也可在“采集 → 群知识 → 编辑目标群”中指定主供应商和复核供应商；复核供应商留空表示跟随主供应商。自定义供应商缺少密钥会明确报错，不会隐式使用 DS。新增时可以只填写 API Key，程序自动生成密钥变量名，并将密钥保存在配置文件旁的 `.env`；编辑时不填新密钥会保留原值。不要把密钥写入报告或聊天中。

AI 用于发现主题、结合上下文理解群内术语、提取知识，以及根据讨论和文件名称/元信息评估文件用途。小文件正文预览可在具体群的 `files.preview_enabled: true` 显式开启，默认关闭；预览只读取有界文本，不执行文件。模型分层切换（`models.tiered_enabled`）、独立复核（`models.review_enabled`）和故障熔断（`models.circuit_enabled`）也都需在具体群显式开启，默认关闭。调用失败时会保守预留预算，避免超出每日上限；本说明不对 AI 价值判断准确率作量化承诺。

程序负责执行群范围、启用状态、批次和预算边界，校验引用与下载文件的大小和哈希。模型返回的来源需通过数据库核验后才能展示。历史回放只生成本地派生结果，不重新发送旧消息。人工设置的术语含义优先，AI 不会覆盖人工修正。

术语仅被提及不会自动启用其解释。模型需提供包含术语、实际解释词义的原消息摘录；程序核对摘录与来源，并要求至少两条不同原文中的释义摘录、原始时间至少相隔 30 分钟，才允许该解释用于后续群分析。缺少原始时间、同文重复、时间不足 30 分钟的多次提及均保留为候选。旧版仅凭提及次数启用的 AI 解释在读取时也按候选处理；人工解释不受此限制。时间间隔也不能保证来自两个独立话题，这个门槛仍不能保证模型对词义的语义判断正确，需结合原文复核。

总结与知识卡可展开全部引用来源；超过 6 条时，其余来源放在“展开其余”区域。分析会要求区分个人体验与一般规律，不把准备使用或“应该可行”写成已验证经验，也不为未解决问题补写工具、训练或机制推论。提示词约束不等于已消除全部此类错误。

文件目录为 `data/knowledge-files`，单文件默认上限 512 MB，群容量预算默认 20 GB。`files.mode: review` 表示文件只进入候选审阅流程，不会自动下载。可以用 `retain-file` 对指定文件发起明确保留。失败文件可用 `retry-files` 按群独立轮转重试。

群知识来源索引和结果存储在 `knowledge.db`；原始消息仍从原有 `bot.db` 按权限和群范围读取，不迁移原库。运行中的 bot 需要重启，才能载入新代码。配置变更也应按部署流程重新载入。

## 命令

群聊命令只访问当前群，且需要对应功能已对该群启用：

```text
群总结 今天
群总结 昨天
群总结 2026-10-12
群总结 最近100条
群知识 关键词
群术语 关键词
```

私聊可指定群号，但仍受现有访问权限限制：

```text
群总结 123 今天
群知识 123 关键词
群术语 123 关键词
```

日期总结按原始消息时间计算。长时间窗口会分批处理；结果会说明已覆盖的消息数量，未处理完时标明部分结果和续跑提示。缺少原始时间的消息不会被错误归入指定日期。

CLI 从仓库根目录运行，`--config` 放在子命令之前：

```powershell
python -m qq_onebot_whitelist.knowledge --config config.yaml status
python -m qq_onebot_whitelist.knowledge --config config.yaml analyze --group 123 --date 2026-10-12
python -m qq_onebot_whitelist.knowledge --config config.yaml analyze --group 123 --limit 100
python -m qq_onebot_whitelist.knowledge --config config.yaml analyze --group 123 --limit 100 --feature extraction
python -m qq_onebot_whitelist.knowledge --config config.yaml analyze --group 123 --limit 100 --feature glossary
python -m qq_onebot_whitelist.knowledge --config config.yaml terms --group 123 --keyword 术语
python -m qq_onebot_whitelist.knowledge --config config.yaml history --group 123 --start 2026-10-01 --end 2026-10-12 --max-batches 3
python -m qq_onebot_whitelist.knowledge --config config.yaml view
python -m qq_onebot_whitelist.knowledge --config config.yaml retry-files --group 123
python -m qq_onebot_whitelist.knowledge --config config.yaml retain-file --group 123 --message-db-id 456 --file-id QQ真实文件ID
python -m qq_onebot_whitelist.knowledge --config config.yaml set-term --group 123 --term 术语 --meaning 人工确认的含义
```

`retain-file` 需要原库中的整数消息 ID 和 QQ 提供的真实文件 ID；文件名不能代替 file ID。`set-term` 可纠正群内术语含义，后续 AI 分析不会覆盖这项人工含义。`terms` 与“群术语”只查询本群术语表，不调用模型；关闭术语学习时不可用。“群知识”只查询本群知识库。`view` 会生成四个独立报告页，并返回兼容的 `knowledge.html` 入口。`status` 显示全局状态及已启用群的功能。

第一版 `notifications` 仅作为预留项，没有自动发送，也不支持向群或个人外发；结果通过本地页面查看。Qt 设置页可编辑全局开关、基础默认参数和逐群知识配置。

## 操作注意

- 开始试点前，先确认模型预算、文件容量与目标群配置。
- `retry-files` 只对指定群重试失败任务；候选审阅模式不会自行下载文件。
- 修改代码后，重启正在运行的 bot 才会加载新代码。
- 群与功能均为独立开关；对一个群的配置不会自动启用其他群。
## 对象用途标签

平台与对象、通用资料主题、对象用途分别展示。具体平台未知时，仍可以归入“虚拟卡”“账号交易”“邮箱”等主题；只有两种分类都缺少依据时才进入“其他与对象待确认”。阅读时还会参考独立的[互联网背景与谐音指代](互联网背景与谐音指代.md)，其定义与当前群友说法分开。

知识页可以先按“破甲工具”“逆向分析工具”等用途筛选，再选择具体对象主题和情形类型。用途标签回答“这个对象是什么、用于什么”，主题回答“讨论谁”，情形回答“这次遇到了什么”。三者与术语解释、使用是否成功分别保存。

每个标签标明“人工确认”或“原文支持”，展开“用途标签依据”可看分类说明和历史消息编号。某工具被分类为破甲工具，不代表本次破甲成功、适用于所有模型或效果已验证。

可以显式保存本群对象定义和已确认别名，例如：

```powershell
.venv/Scripts/python.exe -m qq_onebot_whitelist.knowledge tag-subject --group 338431075 --subject 富江 --tag armor_tool --note "用户确认本群用途，效果需另看原讨论"
.venv/Scripts/python.exe -m qq_onebot_whitelist.knowledge tag-subject --group 338431075 --subject 无限X代 --tag armor_tool --alias 无限二代 --alias 无限四代
```

这一操作会备份知识库，给原文确实提到该对象或别名的已有条目补充主题关联，并重新生成报告；不调用 AI、不改写正文、不合并版本或使用经历。分类按群保存，后续本群 AI 整理即使关闭术语学习，也可使用这些定义识别对象。关闭自动整理后仍可浏览和人工整理既有资料。

别名仅在有明确等同依据时合并。“无限各代”、IG5、Infinite Gen 和 DSh 的拼写或使用场景相似，不足以证明它们是同一对象；旧的合并入口会按各条原文拆分。
