# 日报链接处理设计

## 目标

让日报中的链接可用、可读、可去重，并在不增加 LLM token 消耗的前提下补充网页标题和简介。

## 范围

分三层实现：

1. A：修正 URL 提取、规范化、跟踪参数和 fragment 处理。
2. B：按资源价值筛选并稳定排序日报链接，保留未知链接但置于低优先级。
3. C：仅对最终选中的少量链接抓取 HTML 标题/描述，使用本地缓存和安全限制，不调用 LLM。

不引入第三方短链接服务，不下载文件，不改变现有消息采集和图片分析流程。

## 设计

`summary.extract_links` 使用 ASCII URL 字符边界，避免把后续中文聊天文本吞进 URL，同时继续支持常见 URL 保留字符和中文标点截断。`daily_report.canonical_url` 删除明确的分享/跟踪参数，保留语义查询参数、重复参数和 fragment；`dedupe_url_key` 直接基于规范化 URL 去重，避免不同歌曲、视频或资源版本被错误合并。

日报链接按 `link_score` 分为高价值、普通和未知三档。明确低价值链接仍过滤；高价值链接优先，未知链接保留但数量受日报上限约束。上下文去掉 URL 和重复链接，只保留短说明。

C 层新增标准库 HTML 元数据读取器：只允许 HTTP(S)，阻止 localhost、回环、私网和链路本地地址；连接超时 3 秒，最多读取 256 KiB，仅接受 HTML 内容；解析 `<title>`、`og:title` 和 `description`，失败时回退到现有上下文。元数据按规范化 URL 写入本地缓存，日报构建不因单个链接失败而失败。

LLM 调用链另加 usage 观测：保存接口返回的 `prompt_tokens`、`completion_tokens`、`total_tokens`，失败批次记录错误和退避信息；不改变当前目标图片门控逻辑，也不把网页元数据送入 LLM。

## 验证

测试覆盖：中文粘连、跟踪参数清理、语义查询参数保留、fragment 保留、不同查询 URL 不错误合并、日报排序/限制、HTML 元数据成功与失败回退、内网地址拒绝、LLM usage 记录和失败不推进游标。完成后运行链接/日报/LLM 测试及全量 pytest。
