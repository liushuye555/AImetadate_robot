# 站点多功能记忆 + 网络代理（2026-08-04）

## 目标

1. 链接分类具备**站点记忆**：按域名聚合历史判定，得到"这个网站有哪些功能"的多功能画像；确定站点直接归类（零 LLM），混合站点逐条判定（规则/标题/上下文先行，判不出才调 LLM）。
2. 出站请求支持**代理**（默认 `127.0.0.1:7897`），代理失败自动**直连兜底**；面板新增"网络"设置组。
3. `links.link_judge` 默认改为 `both`（规则判不出的链接才调 LLM）。
4. 修复可靠性：bot 主 WebSocket 连接失败不再直接退出（5→60s 退避重试），断开自动重连；退出时状态如实写 `bot: false`（之前谎报 true 导致面板自动重启不生效）。

## 站点记忆

- **画像源**：历史链接表 + 链接标题/描述元数据，按域名聚合 `link_category` 分类计数：`{域名: {功能: 次数}}`。
- **确定性判定** `deterministic_category`：总数 ≥2 且主功能占比 ≥2/3 且主功能 ∉ {其他, 娱乐视频} → 站点功能确定；否则视为混合站点。
- **用途**：
  - 低价值挽救：确定且主功能有价值时，不再跳过（如网易云音乐 → 音乐）。
  - 分类兜底：单条链接分类为"其他"时改用确定主功能（避免落进"其他"）。
  - LLM 节流：确定站点直接沿用，不调 LLM。
  - 展示：资源页每条链接显示"该站历史功能：×××"，确定站点加标记。
- **混合站点**（bilibili 图文+视频、Civitai 模型+图片等）：保持逐条判定，规则/标题/上下文判不出 → 按 `links.link_judge` 模式调 LLM（按 URL 缓存，不重复花钱）。

## 代理

- 配置：`network.proxy {enabled, host, port}`，默认启用 `127.0.0.1:7897`。
- `netutil.open_url(req, timeout, handlers)`：本地地址永不代理；代理优先，`URLError/OSError/TimeoutError` 自动直连兜底。
- 应用范围：LLM 调用（llm_summary / llm_link_judge / prompt_judge / ai_discussion_judge / collection.ai_match_message）与链接标题抓取（link_metadata）。**图片下载保持直连**，避免代理拖慢采集。
- 面板：config_bridge schema 新增 `network` 分组（启用/主机/端口），Qt 面板 schema 驱动自动渲染，无需重编译。

## 测试

- 画像聚合与确定性判定（多标签、混合站点不判确定）。
- 资源页：确定站点免 LLM + 分类兜底；混合站点仍逐条 LLM。
- 代理：配置解析、直连兜底、本地地址不代理。
- 重连：首次连接失败后重试、退出状态 bot:false。
