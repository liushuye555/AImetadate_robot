# 参数讨论图片的关联与人工纠错

参数词命中只是线索。报告中的图片还需要可追溯的实质讨论：同一条图片消息的说明、明确引用，或同发送者在三分钟内同一图片帖中的参数说明。单独提问、猜测和处理中提示不能作为有效结论。

参数报告优先展示 `image_discussions.context_text`。正文记录原始消息编号、时间（数据库 UTC 时间）、匿名成员编号与引用关系，避免把不同成员的 INT8、FP8 等回答合并成一个设置。后续有效回答会刷新已归档图片的讨论。人工纠错具有更高优先级，自动更新不能覆盖；同群相同内容的图片也继承人工拒绝，不影响其他群的判断。

`selected` 表示有相关实质证据；`pending` 表示尚未确认；`rejected` 表示人工确认应退出参数报告。后两种状态不出现在参数类别及其“全部”主条目中。若一张图还有 AI 元数据或确认混淆等主类别，只取消参数类别中的交叉展示。状态修改不删除原件，不改变图片的归档或保留原因。未确认素材可重新审计。

默认审计仅重查已被标为参数讨论的记录；显式指定编号可以检查任意现有图片，但不会自动把候选图晋升。附近记录按群和本地消息编号前后各最多 256 条检索，再按原始事件时间筛选；极端高频群或原历史缺失仍可能需要人工补证。图片主动明确引用旧参数帖时可超出邻近时间窗。没有原始消息时不会使用当前最新聊天替代。

## 本地操作

先预览；此命令只读，不迁移数据库，也不启用 AI：

```powershell
.venv/Scripts/python.exe -m qq_onebot_whitelist.params_context --project-dir . audit
```

应用前先备份数据库，然后加入 `--apply`。可重复指定 `--image-id` 缩小范围。应用只写派生判定表，不改原图和消息。

人工纠错示例：

```powershell
.venv/Scripts/python.exe -m qq_onebot_whitelist.params_context --project-dir . feedback --image-id 86142 --status rejected --reason "歌单封面，与生成参数无关"
```

人工 `selected` 会重新构建问答及证据。若没有可关联的实质讨论，命令会提示先补全证据，避免生成空的有效讨论。之后重新构建报告即可更新展示。

这次纠错不会开启新的可选功能，也不会自动上传历史图片做视觉判定。已有参数 LLM 复核仍遵循原配置。仅靠文字关联无法判断所有图片的价值，待确认列表也不等于无价值列表。
