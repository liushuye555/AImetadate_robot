# 全量历史补抓

在项目目录运行：

```powershell
.\.venv\Scripts\python.exe -u -m qq_onebot_whitelist.full_history
```

任务读取当前框架和凭据，归档当前账号所有未屏蔽群的历史消息。默认每页 200 条、并发 2 个群，每页间隔 0.3 秒，不受启动补抓的 200 页上限限制。QQ 官方通道没有群历史接口，不能使用此命令。

消息正文、原始消息对象（含图片、文件等引用）及链接写入现有 `data/bot.db`，沿用消息唯一键去重。此归档路径不会执行历史命令、自动回复、转发或 AI 分析，也不会下载所有附件本体。消息和链接按消息原始时间写入日期索引，避免旧链接被日报算成今天新增。

“最近消息”和“最近链接”按日期排序，避免较晚补进数据库的旧内容挤占最近记录。归档数据仍可被项目已启用的后台分析功能读取；独立归档任务本身不发起分析。数据库短时忙碌时重试同一页，提交成功之后再推进断点。

`run/full-history.json` 每页保存断点和各群进度，包含新增条数、页数、最早/最晚消息时间、状态。中断后重新运行同一命令，会从已保存的锚点继续。已返回空页或无法继续向前的群保留记录并结束，同一检查点恢复时直接跳过，不再探测该边界。检查点绑定框架和 QQ 账号，更换账号时请指定新的 `--state` 文件；已有记录继续去重。独立任务锁会拒绝同时运行两个相同检查点任务。失败的群会记录错误类型，并继续处理其他群。

SnowLuma 使用真实 `message_id` 翻页（负数 ID 也是有效 ID）；其他当前兼容框架沿用 `message_seq`。遇到整页已入库记录时仍继续向旧记录翻页，不把“无新增”当作结束。

状态含义：

- `running`：正在抓取。
- `retrying` / `failed`：请求重试或失败，断点保留。
- `available_end`：接口返回空页，当前可获取记录已到边界；不能据此证明原始聊天从第一条开始全部可获取。
- `empty_unverified`：第一页即返回空数据，可能是框架没有该群的历史起点，不视为已补齐。
- `no_progress`：接口仍返回消息，但最旧锚点重复，不能继续向前；按用户要求停止该群的历史补抓，保留已归档记录，不再重试该边界。

任务总状态 `finished` 表示选中群均达到接口空页边界；`finished_with_limits` 表示抓取已结束，其中有群无法继续向前或首个请求返回空数据；`needs_attention` 表示仍有真正的执行失败。前两种状态正常退出，均不代表平台未提供的消息已恢复。`available_end`、`no_progress` 和 `empty_unverified` 在同一检查点恢复时均跳过。需要主动重新扫描这些群时，使用新的 `--state run/full-history-rescan.json`。

可用参数：`--config`、`--state`、`--count`、`--delay`、`--concurrency`（1–4）。任务与实时采集可并行运行，无须重启 QQ 或管理器。
