# 项目交接文档

## 1. 项目概况

项目名称：QQ OneBot 白名单资源机器人
项目目录：

```text
项目根目录
```

运行方式：NapCat + OneBot v11 正向 WebSocket + Python asyncio/websockets。

当前工作区是 Git 工作树，当前分支为 `codex/qt-control-panel`。修改前保留用户已有未提交改动，不要执行 reset、stash、checkout 或清理无关文件。

## 2. 当前运行环境

```text
OS: Windows
Python: 3.11+
包管理: uv
OneBot WS: ws://127.0.0.1:3001
NapCat WebUI: http://127.0.0.1:6099
NapCat: runtime\NapCat.Shell.Windows.Node
```

bot 后台启动脚本：

```text
scripts/windows/start-qq-onebot-whitelist-hidden.ps1
```

停止脚本：

```text
scripts/windows/stop-qq-onebot-whitelist-hidden.ps1
```

停止脚本会先写入 `run/manual-stop` 和停止状态，再终止进程，避免托盘自动重启在停机瞬间抢先拉起第二份实例；启动成功后会清理该标记。

## 5. 当前核心行为

### 消息回复

- 私聊：仅白名单用户，查询全局数据。
- 群聊：白名单用户/群或群管理员，默认必须直接 `@机器人`。
- 群命令只查询当前群，防止跨群泄露。
- 命令 `/` 可省略。

### 历史补拉

启动历史补拉使用独立 WebSocket 后台执行，主 WebSocket 立即处理实时事件，避免补拉期间吞掉私聊命令。

消息以 `(scope, message_key)` 去重；`message_key` 优先使用 `message_id`、`real_id`、`message_seq`。

### AI 上下文

- Provider：`ds_v4_flash`。
- 所有非黑名单群。
- 每 200 条一批。
- 每 15 分钟检查一次。
- 新增累计达到 300 条触发。
- `ai_context.allowed_windows` 默认为空列表，即全天允许；用户可配置多个本地时间窗口，窗口外继续积攒。
- 输入使用 `#消息ID U用户别名 HH:MM` 紧凑格式。
- 每批用户表包含群名片/昵称，raw_json 保存别名到真实用户映射。
- 摘要覆盖有信息量的群聊主题，AI 绘图内容仍作为重点，不再把非 AI 讨论统一总结为“无有效内容”。

### 图片

- 新下载图片写入每次独占的临时文件，并经过 Pillow `verify()` 和完整 `load()`；空文件、截断或无法完整解码的文件不会进入归档，避免相同 QQ 链接并发下载互相覆盖。
- AI 元数据图片长期归档；群友好评、AI 上下文命中和显式聊天记录收藏也可进入长期归档。
- 明显表情包、小尺寸方图和 GIF 会过滤，但显式保存的聊天记录图片使用 `chat_record_saved` 强制保留。
- `data/images/ai/` 不使用 500MB 缓存预算；`data/images/candidates/` 才是 TTL 临时候选。
- `/修复图片 <ID>` 先复用同批正常归档，找不到时才使用数据库原始 URL；新文件完整校验后才原子替换更新归档和数据库，扫描命令只处理已归档的损坏文件。
- Gilbert 检测与还原上限保持一致；确认的混淆图在有上下文分类时同时写入 05 主分类和 02/03 交叉分类。

### 聊天记录图片收藏

- 只在私聊中处理“回复一条合并聊天记录后发送 `/保存图片 [分类名]`”。不填分类名默认 `未分类`。
- 支持 `message`/`content` 两种节点字段、嵌套合并记录最多 16 层；`seen_ids` 防循环和重复抓取。
- 图片按 SHA-256 去重；记录写入 `images.retention_reason='chat_record_saved'`、`saved_category` 和 `raw_json`，页面生成到 `data/view/06_聊天记录收藏/<分类名>/`。
- 旧 `favorites` 表保留，不再自动保存新的私聊转发；`收藏夹` 只返回当前显式图片保存用法提示。

### 资源链接与文件

- 链接按规范化 URL 去重，根路径的 `/` 与无 `/` 合并；保留语义 query/fragment，仅删除明确 tracking 参数，并跨群合并。
- 已知短链尝试解析最终 URL，结果缓存在 `link_metadata.resolved_url`；未解析的 `b23.tv`、小红书等短链不展示。分类优先使用最终域名/路径，再使用网页标题、描述和链接附近上下文，避免整条长消息的泛关键词污染。
- 已知路径规则：Tusi 模型页 → `AI模型`、图片页 → `图片`，Tusi/RunningHub/Comfy 工作流页 → `AI工作流`，RunningHub AI 应用页 → `AI在线服务`，Comfy 下载页和 GitHub 仓库 → `AI工具插件`。视频分为 `音乐视频`、`AI教程视频`（教程/部署/工作流/提示词/节点/实测）、`AI资讯视频`（模型、ComfyUI、AI 产品更新/发布）和 `娱乐视频`；视频规则优先于泛教程词，避免聊天里单独出现“学习”就误判教程。Linux DO、V2EX、Reddit、贴吧、Koishi 论坛归为 `技术社区`；含中转/反代/额度/倍率等明确信号的 API 站归为 `AI中转服务`；CivitAI、Tensor Art、SeaArt、PixAI 的作品/图片/用户页归为 `AI作品展示`。日报链接行以 `[分类]` 前缀展示同一分类结果；`AI教程视频` 和 `AI资讯视频` 即使在泛视频平台也不会被低价值过滤，纯 `音乐`、`音乐视频`、`娱乐视频` 和 `图片` 不发送日报但仍留在资源页。图片托管页和图片直链不进入资源页面；网盘统一为 `网盘资源`；明确娱乐、广告和泛分享才过滤。
- 资源页面提供安全外链、复制链接和折叠后的完整 URL；文件按小写文件名+大小+类型去重并跨群合并，不下载群文件。
- 本地页面不展示原聊天上下文，数据库旧记录不删除，HTML 从数据库全量重建。所有图片图库保持单页入口但按需加载：首批默认 120 张，后续通过分类目录下自动生成的 `chunks/chunk-*.js` 在滚动或点击按钮时追加；上下文图片页也使用同一机制。

### 群保活与复读

- 入口先过滤 `user_id == self_id` 的机器人自消息，不采集、不回复、不更新群活跃度。
- 复读要求达到阈值的不同外部发言人；同一用户连续重复不会重复触发。
- 管理员清群公告触发即时保活，非管理员不触发；同一群有 60 秒冷却，避免机器人重复发送。

## 8. 已知风险和注意事项

1. OneBot action 调用与事件接收不能共用一个阻塞 `ws.recv()` 流；历史补拉已改为独立连接，后续修改不得退回旧结构。
2. `send_reply` 当前记录发送动作，但普通回复未统一等待 OneBot echo；重要发送可考虑引入统一请求路由。
3. NapCat 默认使用项目内 `runtime/`；仅自定义外部路径时需要配置覆盖。
4. 停止脚本会停止 NapCat 和 bot；若只想重启 bot，应只结束命令行包含 `qq_onebot_whitelist.onebot` 的进程。
5. SQLite `CURRENT_TIMESTAMP` 是 UTC 语义；展示/调度应明确使用 Python 本地时间。
6. 历史数据库可能包含早期重复记录；新记录已去重，但未执行危险的批量删除历史记录。
7. `data/view/` 可能很大，因为使用硬链接构建浏览视图；通常不额外占用数据空间，但不能把视图当唯一数据源。
8. `.env` 含 API 密钥，禁止公开。

## 9. 推荐后续维护顺序

1. 修改前运行测试。
2. 为 bug 先添加回归测试。
3. 修改代码。
4. 运行完整测试。
5. 运行 maintenance 重建本地页面。
6. 仅在代码运行逻辑变化时重启 bot；纯 HTML 重建无需重启。
7. 检查 `logs/bot.log`、OneBot 3001 端口、6099 端口和一次私聊“帮助”回复；代码或 bot 配置变更后再重启服务。
