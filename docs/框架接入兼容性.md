# 框架接入兼容性

本项目将消息接入与框架进程管理分开。机器人使用 OneBot v11 正向 WebSocket；更换兼容端点时沿用当前数据库、图片、白名单和报告，无需迁移业务数据。管理器统一提供“检查并切换框架”和“恢复上次框架”操作：选择提供商并填写端点与 Token 环境变量名后，系统先验证目标连接，再应用接入设置。切换和恢复都会停止业务机器人并保持管理器运行；切换失败时原接入配置不变。恢复上次框架适用于各框架，与 SnowLuma 专用部署和自动检测无关。详细流程见部署说明。

QQ 官方机器人已增加独立适配器和扫码绑定入口，使用方式与验证边界见 [QQ 官方通道接入](QQ官方通道接入.md)。原调研见 [QQ 官方方案与 DSH 插件调研](QQ官方方案与DSH插件调研.md)。

## 接入范围

| 设置中的框架 | 连接方式 | 本项目管理框架进程 | 验证范围 |
| --- | --- | --- | --- |
| 通用 OneBot v11（external） | 配置的 ws/wss 地址 | 否 | 本地协议契约测试 |
| QQ 官方机器人（qqofficial） | 官方 WebSocket + REST API | 仅管理本项目业务进程 | 本地 HTTP/WS 测试；真实扫码与群权限待验证 |
| NapCat（napcat） | 同上 | 仅显式开启且地址为本机时 | 本地协议契约测试；原有启动器保留 |
| LLBot（llbot） | 框架提供的 OneBot v11 端点 | 否 | 本地协议契约测试，未用真实账号验证 |
| SnowLuma（snowluma） | 框架提供的 OneBot v11 端点 | 内置部署可随管理器启停；也可连接外部部署 | 本地协议与部署测试，真实账号收发待验证 |
| Lagrange.OneBot（lagrange） | 框架提供的 OneBot v11 端点 | 否 | 本地协议契约测试，未用真实账号验证 |

SnowLuma v2.4.2 的 Windows 安装、首次 WebUI 配置和切换步骤见 [SnowLuma 部署与切换](SnowLuma部署与切换.md)。

这些名称用于配置和状态展示，不保证某个框架版本提供全部接口。需要框架启用 OneBot v11 正向 WebSocket 服务，并允许客户端调用 API。仅提供 Milky、Satori、OneBot v12 或反向 WebSocket 的服务暂不能直接连接，需要新增协议适配器。配置协议为 Milky/Satori 时会明确报错。

## 配置示例

在管理器“设置”的运行配置中选择框架、填写连接地址和可选管理页；也可编辑 config.yaml 的 onebot 段：

```yaml
onebot:
  provider: external  # external / napcat / llbot / snowluma / lagrange
  protocol: onebot11
  ws_url: ws://127.0.0.1:3001
  manage_process: false
  webui_url: ''       # 有管理页时填写实际 http(s) 地址
  access_token_env: ONEBOT_ACCESS_TOKEN
  max_message_mb: 16
  disabled_actions: []
```

将实际 Token 写入项目 .env 的 ONEBOT_ACCESS_TOKEN，或同名环境变量。SnowLuma 切换使用独立的 SNOWLUMA_ONEBOT_TOKEN，不覆盖原有 Token。连接使用 Authorization: Bearer 认证；主消息连接、历史补拉、转发查询、群列表、报告发送及群文件下载共用连接配置。设置页只显示环境变量名，不显示 Token。

更换框架请在管理器运行设置中选择提供商并填写端点与 Token 环境变量名，使用“检查并切换框架”确认连接后，再从总览启动机器人。该操作会先校验配置与目标连接，成功后才应用设置；无论成功或失败，业务机器人都会保持停止。“恢复上次框架”恢复最近一次不同框架切换前保存的 OneBot 配置，并保留其他设置；重复应用同一目标时不会替换该恢复点。外部框架须已自行部署并运行；SnowLuma 另有专用安装和启停入口，首次登录仍由用户完成。通用恢复操作与 SnowLuma 的专用部署、自动检测无关。远程 NapCat 不会触发本机 NapCat 启动器。旧配置未填写 provider 时保留原 NapCat 行为；新部署建议显式设置 external 和 manage_process: false。

## 可选能力与检查

实时消息兼容消息段数组和 CQ 字符串；转发接口兼容 messages 对象与直接数组，并转换常见 content/sender 字段。API 调用关联 echo、设定超时并检查 retcode，接口失败不会作为空结果成功返回。

历史补拉、合并转发、群文件目录和下载地址依赖框架扩展接口，支持范围可能不同。可在 disabled_actions 中填写不支持的 API 名称，例如 get_group_msg_history；禁用后不会发起该调用。图库、已有报告和本地数据库查询不依赖这些接口。报告发送需要 send_group_msg 或 send_private_msg。

从项目根目录执行只读检查：

```powershell
.\.venv\Scripts\python.exe -m qq_onebot_whitelist.control gateway-info
.\.venv\Scripts\python.exe -m qq_onebot_whitelist.control gateway-check
.\.venv\Scripts\python.exe -m qq_onebot_whitelist.control gateway-check --group 目标群号
```

gateway-info 只显示配置，不建立连接。gateway-check 查询版本、状态、登录信息和群列表；指定群号时另外检查一条历史和群文件根目录。结果区分 supported、unsupported、disabled、timeout、failed。检查不发送消息、不登录、不变更群成员；也不会检查需要具体消息 ID 或文件 ID 的所有扩展 API。

管理器分别展示接入框架连接、业务进程、QQ 登录状态。只有 get_status.online 明确返回布尔值才确认 QQ 在线；仅返回缓存账号资料时显示“状态未知”，不会据此认定已登录。

兼容性测试使用本地模拟 OneBot 服务，验证认证、回包格式、错误码、超时、大消息及框架切换和恢复。SnowLuma 的安装、配置和生命周期另有测试；真实 QQ 收发及会话长期稳定性仍需实际接入后验证。
