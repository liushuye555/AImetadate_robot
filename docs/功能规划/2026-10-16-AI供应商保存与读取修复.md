# AI 供应商保存与读取修复（2026-10-16）

用户指出 FreeWB 应已保存在配置中。实际核对发现，`config.yaml` 中存在名为 `freehy` 的 WorkBuddy 接口，且 `ai_context.provider` 已选中它；按 FreeWB 名称搜索而未检查配置内容，导致此前漏判。

## 根因与修复

1. 供应商编辑框允许 API Key 不带环境变量名，但保存信号只有两项均非空时才写密钥，导致 API Key 被静默丢弃。现在只填密钥时自动生成合法、稳定的环境变量名；缺少密钥来源则阻止保存。编辑保留已有附加字段，ID 不可在编辑中改名，重复 ID 被拒绝。
2. 群知识的供应商解析原来只认识内置 default 和 ds_v4_flash，设置页新增项没有接入。现在知识分析、复核和反馈优化共用保存的供应商注册表；默认跟随全局选择，也可逐群指定。自定义供应商不自动退回 DS；缺少密钥会明确报错。旧配置未显式选择全局供应商时保留原有默认路由行为。
3. 群知识页的供应商列表原来固定为两个内置名称，现在动态显示已保存的供应商，保留未知历史选项，并可单独选择复核供应商。
4. 环境文件现在按配置文件所在目录定位，避免工作目录不同导致读取另一份 `.env`。内置别名、自定义连接及复核均有回归覆盖。
5. 密钥保存通过子进程标准输入传递，不出现在进程参数；环境文件采用原子替换，拒绝无效变量名与多行值，保存回包不返回密钥。设置 schema 过滤意外写入的明文密钥字段，超时字段保留数字类型。
6. 删除供应商原先会被后端深度合并逻辑恢复；现在完整供应商列表按整表替换，保留其他配置。

## 修复时的本机密钥状态

只检查了密钥是否存在，没有在报告中记录密钥内容。当时 `freehy.api_key_env` 为空，项目 `.env` 没有对应凭据；现有配置备份中的该项也为空。接口的无鉴权 `/models` 请求返回 401，不能按免密接口使用。

因此不能恢复从未持久化的输入。需要在修复后的“设置 → AI 供应商 → freehy → 编辑”中重新输入一次 API Key；环境变量名可以留空，由程序自动生成。该动作应由用户完成，密钥不需要发到聊天中。没有用假密钥或其他供应商密钥替代，也没有继续调用 DS。剩余群知识语义复核仍待有效 FreeWB 凭据保存后完成。

后续用户已明确提供并授权使用 WorkBuddy 凭据，现已保存、完成 200 鉴权检查及 30 次真实话题复核。该等待条件已解除，见 [内容复核与供应商状态](2026-10-16-群知识内容复核与供应商状态.md)。
