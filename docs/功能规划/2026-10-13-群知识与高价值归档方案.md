# 群知识与高价值归档方案

日期：2026-10-13。状态：已按用户确认进入第一版开发。完整规划包含后续增强，当前实现与验证范围见《2026-10-13-群知识开发与历史验证》及《群知识功能使用说明》。AI 主导理解与判断；所有新增功能默认关闭，必须主动开启。

规划阶段完成代码清点与历史统计；后续开发阶段已实现第一版并开展独立库中的 AI 历史抽样验证。运行配置保持关闭，没有发送新群消息或下载真实群文件。

## 1. 产品目标

让机器人从消息与图片归档工具扩展为按群管理的知识库：能解释一个时间段讨论了什么，提炼可复用结论，保留相关文件本体，并让每条结论能够回查原消息。

用户要求的两条匹配路径：

- **专群匹配**：为特定群指定一个或多个主题，例如 AI 绘图、AI 辅助逆向、软件开发。应用相应术语、资源类型与价值标准。
- **泛匹配**：跨主题发现教程、排错经验、实测对比、工具、资料、公告和有结论的问答。允许新主题出现，不依赖预先列全关键词。

两条路径可同时启用。主题相关度、知识价值、证据可信程度分别记录；命中主题或黑话不等于高价值。

### AI 主导的处理原则

主题理解、讨论归并、行业黑话解释、知识提取、资源价值判断与语义去重主要交给 AI。用户主要配置关注方向、保留偏好与预算，不需要维护大量关键词或逐条审核普通结果。

程序负责可以确定验证的部分：消息采集与时间、群范围、证据 ID 核验、任务状态、实际文件哈希与大小、磁盘配额和通知目标。关键词用于帮助检索上下文、提示已知实体和低成本降噪，不作为语义分析的必经门槛。

建议的 AI 处理流程：

以下流程仅在全局、对应群和对应功能均已由用户主动开启时执行。AI 可以自主完成已开启任务中的理解和判断，不能自行开启其他功能或把新群纳入处理。

1. 按群持续读取新增记录，保留引用、图片/文件标记和必要上下文，只过滤确定的系统事件或完全重复材料。
2. 由轻量模型阅读所有待分析讨论批次，识别话题、问答关系、可能有用的结论、新术语与资源。没有关键词、链接或图片也能成为候选。
3. 对复杂、存在歧义、涉及高价值资源或需要跨批次证据的候选，由能力更强的模型结合检索到的同群历史复核。普通明确结果可由轻量模型直接完成。
4. 输出结构化知识卡片、主题与证据；程序核验引用是否真实存在并属于允许范围，再自动入库和执行已配置的保留策略。
5. 复用同一次抽取结果生成日报、周报与检索索引，避免每个页面重复调用模型。

群消息中的指令被当作待分析内容，不改变分析任务、群范围或文件保留政策。分析模型可以建议调整主题、解释和筛选偏好，不能自行修改权限、发送目的地或磁盘配额。

轻量/复核模型使用供应商实际提供的 API 模型配置；Codex 子代理的模型名称不直接当作机器人可调用的 API 模型。先在固定历史样本上比较单模型和分级处理的质量、延迟与用量，再选择实际组合。

| 能力 | 现状 | 扩展方向 |
| --- | --- | --- |
| 按群采集 | 已有 `collection.groups`，控制图片、链接、文件、转发采集 | 在此基础上加入知识配置；采集权限与分析主题分开 |

| 图片上下文 | 增量批次、引用解析、质量信息 | 保留作为图片专用分析；与群知识通过关联表连接 |
| 资源页与日报 | 已有去重、链接用途、按群展示 | 加入知识卡片、按群阈值、文件本体状态与检索 |
| 群文件同步 | 已有文件扫描、下载暂存、WebDAV 上传 | 增加本地长期保留、价值筛选、哈希校验与版本 |
| Qt 管理面板 | 已有群列表、采集编辑、报告预览与浏览入口 | 复用群选择，增加“知识规则、术语、精选、文件”配置与页面 |

确证的优化点：

1. `commands.py` 的“最近总结”调用 `llm_summary.py`，而其系统提示词明确要求“不要总结聊天主题”、只提取可复现图片的参数；普通讨论可能收到 `NO_REUSABLE_IMAGE_CONTEXT`。应建立独立的群总结任务，保留图片任务语义与已有测试。
2. `ai_context_analyze.py` 只有批次存在目标图片消息时才调用分析。因此纯文字教程与经验没有独立提炼路径。831 批中的空摘要不能当作泛知识无价值的证据。
3. `collection.py` 仅将 model/archive/workflow 类文件加入 `files` 索引。PDF、文档、源码脚本及逆向工程资料不能仅凭现有类型规则得到完整索引；工作流 JSON 也需要识别内容，不能因后缀是 JSON 就判高价值。
4. `commands.py` 的“资源/文件”分支使用全局 `format_resources()`，未传本群范围。设计中的新功能及现有资源命令都应强制群范围过滤，避免群内返回其他群记录。
5. 文件同步目前上传后清理暂存文件，属于云同步流程，没有独立的本地长期文件库。资源索引与文件保存状态应分别表达。
6. 现有文件列表按名称、大小、类型合并，不能用于证明内容相同或决定删除副本。
7. `should_run_ai_context()` 合计所有群的新增数量后使用全局阈值；新知识任务应按群维护数量、时间与游标，使小群也能得到分析机会。
8. `file_sync.process_pending()` 内有同步下载与上传调用，存在长时间占用事件循环的风险。扩展大文件归档前应迁移到独立工作任务，并测量实时回复延迟；本轮未进行延迟实测。

## 4. 按群独立配置

一份群配置应能表达以下内容：

### 默认关闭与主动开启

- 新知识模块的全局开关默认关闭。
- 已记录群、未配置群及新加入群的知识开关默认关闭，不自动沿用采集白名单或主题建议启用。
- 每群的群总结、知识提取、术语学习、文件保留、通知分别有独立开关，全部默认关闭；日总结、周总结和历史回放也默认关闭。
- 运行条件是“全局开启 + 指定群开启 + 对应功能开启”。开启群总结不会连带开启知识入库、术语学习、文件下载或消息发送。共享分析结果也只能写入或执行已开启功能的输出。
- 选择主题、填写计划、设置容量、保存配置或接入模型只改变偏好，不隐式打开开关。依赖的功能尚未开启时界面提示缺少什么，不自动开启依赖。
- 功能关闭时，手动命令提示该功能未开启并提供开启入口，不通过一次查询隐式修改长期配置。
- 重启和配置迁移保持原有开关值，新增字段缺失一律视为关闭。已有采集、图片分析和资源日报继续使用原来的配置，不由新模块替换或重置。
- 主动关闭后停止新任务、下载与通知；执行有外部效果的操作前再次检查开关。已保存的知识和文件继续保留，正在完成的下载仅整理已产生的临时数据，不据此继续上传或推送。

界面提供按群的“启用功能”选择；开启前展示所选功能、处理群、是否分析历史、是否调用 AI、是否保存文件和是否发送消息，用户一次主动保存即可生效，不对普通分析结果逐条询问。

| 配置组 | 可配置项 |
| --- | --- |
| 分析范围 | 全局/群/功能独立开关、是否处理历史、允许分析时间与每日预算 |
| 匹配模式 | 专群、泛匹配、同时启用；专群可选多个主题 |
| 主题定义 | 主题模板、自定义主题描述、AI 建议主题、正反例、偏好内容类型 |
| 术语 | AI 自动发现与解释、证据充分时群内启用、歧义复核、修正与禁用 |
| 总结 | 默认关闭；主动开启后选择手动/日/周总结、时间窗口和详细程度 |
| 精选 | 默认关闭；主动开启后设置入库阈值、每天上限、排除内容与最低证据条件 |
| 文件 | 默认关闭；主动开启后选择自动保留/人工指定、类型、大小、群配额和保留策略 |
| 通知 | 默认关闭；开启分析后可仅在本地展示，外发需单独开启并指定目标 |
| 历史回放 | 默认关闭；主动选择日期范围和分析版本后重算，不重复发送旧内容 |

优先级：群黑名单与群数据边界 > 群级显式设置 > 主题模板 > 全局默认。手动保留可跳过自动价值门槛，但仍遵守群权限和文件保存限制。

没有知识配置的群继续遵循现有采集设置，新知识功能默认不自动启用。`collection.groups` 控制收什么，新知识配置控制如何分析与保留，两个含义不能混用。

## 5. 群总结

支持“今天/昨天/指定日期/指定时段/最近若干条/本周”的总结。群里默认只看本群；有权限的私聊可选择单群或多个群，跨群结果明确标注来源。

输出聚焦：

- 主要话题及各自结论，不把闲聊逐条改写。
- 有价值的问答：问题、尝试、解决方式、结果与适用条件。
- 新资源、实测对比、重要公告与明确截止时间。
- 尚未解决的问题、分歧与缺失的证据。
- 可回查的原消息编号和关联图片、链接、文件。

时间处理：新增可索引 `event_time`，优先采用原始 OneBot 时间；`seen_at` 留作入库时间。缺失原始时间时标注“时间未知”，默认不混入指定日期总结。时区统一按 Asia/Shanghai 展示。

生成流程：按原始时间取同群消息 → 恢复引用与必要上下文 → AI 识别讨论片段与话题 → 提取结论与知识卡片 → AI 合并话题、核对分歧并生成总结。分片允许边界重叠，再按来源 ID 去重，避免问题在前一批、答案在后一批。跨窗口引用只作上下文，注明其时间，不算作本窗口新消息。

模型不可用时返回明确的规则摘要与处理状态；不展示图片任务内部标记，也不把失败当成“群里没有有用信息”。

拟新增命令：`群总结 今天`、`群总结 昨天`、`群总结 2026-10-12`、`群总结 最近200条`。长任务后台执行，结果在本地报告可查看。

## 6. 高价值信息的获取

基本处理单位是讨论片段，不是独立消息。“换这个就好了”本身很短，结合被引用的报错与后续验证可能具有价值。

专群匹配向 AI 提供群关注方向、已确认的术语和代表性历史案例，由模型判断语义是否符合；泛匹配让 AI 自行识别讨论领域并判断是否有可复用信息。两者不要求关键词命中。AI 也可以建议群的新主题，初次作为可解释的建议展示，不直接覆盖用户指定的关注方向。

### 两条匹配路径

| 维度 | 专群匹配 | 泛匹配 |
| --- | --- | --- |
| 主题 | 使用群选定的主题、术语和示例 | 识别新主题、工具与问题类型 |
| 候选 | 领域资源、关键参数、复现步骤、技术结论 | 教程、解决方案、对比、资料、明确公告 |
| 无法理解 | 检索同群历史，由 AI 复核；仍有歧义时待确认 | 识别可能的新主题，保留上下文和不确定性 |
| 混合群 | 一段可对应多个主题 | 与专群结果统一去重，记录匹配来源 |

“专群优先 + 泛匹配兜底”适合多数技术群。非主主题内容仍可成为高价值候选，由群级设置决定是否自动收录。

### 价值判断

初始维度为：可复用性、信息完整性、证据强度、主题相关度、新颖性与时效。聊天热度、发言次数、“大佬/牛/好用”等赞美只作辅助信息，不能作为主要得分依据。

这些维度交给 AI 结合整段讨论评估，返回简短理由、证据和不确定性，不使用关键词次数机械计分。模型自行给出的置信度不作为唯一依据：需结合证据完整性、复核结果和历史验证表现决定自动收录等级。明确结果自动入库，只有歧义、证据不足或配置要求人工判断的条目进入待确认。

对近似知识，AI 判断它是重复分享、增加了条件、修正了旧结论，还是新的方法；程序保存关系和版本，避免相似文本被一律丢弃。

结果分为：精选、待确认、普通线索、忽略。每条都说明收录原因；入库门槛与通知门槛分开，防止有用信息因推送额度耗尽而丢失。

建议精选卡片字段：标题、类型、主题、问题/结论/步骤、适用软件与版本、验证状态、价值理由、原消息证据、关联资源、修正记录、更新时间。验证状态明确区分“群友说法”“有复现步骤”“有结果反馈”“存在争议”。

找不到证据的细节保持为空；不能把模型推断写成原聊天中的事实。模型返回的消息 ID、链接与文件关联需用数据库核验。

## 7. 行业黑话与群专属术语

词表分为三层：主题通用术语、群专属别名、待确认候选。每条记录主题、规范含义、别名、示例来源、置信程度、适用群、状态与版本。

历史里的“炼丹、跑图、抽卡、底模”可以作为绘图词表候选。“抽卡”可能指反复生成抽取满意结果，也可能是游戏活动；“逆向”可能指反推提示词，也可能指二进制分析。通过共现实体、引用对象、群主题和上下文判义，不能全局替换成单一解释。

自动发现流程：

1. 由 AI 在讨论分析时发现陌生词、缩写、别名及可能的新义；词频和共现仅辅助发现，排除账号、随机串和密钥。
2. 检索该词在同群不同时间的代表性上下文，让 AI 提出解释、列出支持证据并检查其他可能含义。
3. 有多个上下文支持、解释一致且复核通过时，自动在本群启用并记录解释版本；仅有单次猜测、解释冲突或缺少证据时保留为候选。人工只需处理少量歧义或主动纠正。
4. 自动启用的解释仍可修正或停用；出现反例时降低确定性并重新复核。词义变更创建新版本，历史分析可指定版本重算，不自动推广到所有群。

术语自动启用只影响理解。文件自动保留和推送还必须满足对应知识/文件的完整证据判断、群策略与预算，不因某个新词获认可而单独触发。

逆向主题先提供工具、工程资料、报错与分析过程的初始分类；再用指定逆向群的实际消息校准。当前历史库不足以证明已理解这个群的黑话。

## 8. 高价值文件本体保留

文件信息索引、价值判断、文件下载和存储副本是不同状态，页面必须显示清楚。

### 保留来源

- AI 从讨论中识别出有价值且有明确用途的工作流、资料或脚本。
- 按群指定类型的自动保存规则。
- 人工回复文件发送“保留文件”，或在待确认列表选择保留。
- 定期补扫仍可访问的群文件树，发现未记录资源。

### 保留策略

- 本地长期文件库为基础，可选 WebDAV 副本；暂存目录不承担长期存储。
- 流式下载到临时文件，校验实际大小与 SHA-256，完成后原子移入归档。
- 用内容哈希识别相同文件；保存所有来源群、原文件名、发布时间与讨论关联。同名不同内容保留不同版本。
- 工作流 JSON、脚本和资料可解析内容建立摘要；模型与大型二进制优先解析元信息，不靠上传整个文件给模型判价值。
- 文件价值由 AI 综合文件内容摘录、讨论中的用途、版本、验证反馈与同群已有资源判断。程序提供受限预览或元信息，不能仅因文件后缀、名称或夸赞而自动认定有价值。
- 小文件可按群预算先下载到暂存以提取内容，再由 AI 决定长期保留；大型文件先评估用途和元信息，价值不明确时保持索引或待确认。页面区分临时查看与长期保存。
- 扩展 PDF、Markdown、文本、源码脚本与逆向工程资料的索引类型；ZIP 内资源可受限读取目录和小文本，不自动执行脚本或无限展开。
- 单文件大小上限、群配额、全局余量和手动固定保留分别配置。固定保留文件不因自动候选过期而删除。
- 失败按下载、过期 URL、校验、磁盘空间和上传阶段记录，分别重试。使用有效 QQ file_id 重新请求下载地址，不能把旧 URL 或文件名当成一定可用的 file_id。
- 云副本是否完成校验单独记录；只有确认已有持久副本时才清理暂存。

建议状态：仅索引、待审核、待下载、下载中、已本地保存、已备份、链接失效、校验失败、空间不足。卡片展示文件用途、来源证据、版本与保存位置。

## 9. 历史记录驱动现有功能优化

先修正分析语义和数据边界，再用历史样本改进 AI 提示、主题说明、术语与检索示例。

AI 定期归纳“误收、漏收、术语误解、文件价值误判”等反馈，提出新的分析版本。历史回放对照新旧结果，人工只审查关键差异与抽样结果，通过后再切换版本。第一版采用提示与示例迭代，不直接承诺模型训练或微调；AI 也不能仅凭自身复核就宣称质量提升。

| 优先级 | 优化 | 验证方式 |
| --- | --- | --- |
| P0 | 最近总结与图片证据任务分开 | 普通讨论有正常总结，图片参数任务保持既有表现 |
| P0 | 群资源命令及新检索按群过滤 | 两群同类资源混入测试，群内结果不越界 |
| P0 | 原始消息时间与入库时间分开 | 回填旧消息后不进入“今天聊了什么” |
| P0 | 文件页区分索引与已保存本体 | 已保存状态必须有可验证的持久副本 |
| P1 | 回复链与批次边界处理 | 跨批次问答、参数与图片正确关联 |
| P1 | 每群独立游标、阈值与等待上限 | 大群持续活跃时小群仍能定期总结 |
| P1 | 内容去重、版本与来源分离 | 跨群重复分享合并文件副本，保留各群来源 |
| P1 | 术语与主题分群校准 | 绘图“抽卡”与游戏“抽卡”不混判 |
| P1 | 文件任务移出实时回复通道 | 大文件下载期间回复延迟满足约定目标 |
| P2 | 检索与历史问答 | 答案有原消息证据，不够信息时明确缺失 |

历史回放只生成派生结果，不重新走实时回复、复读或转发流程。历史分析游标与实时增量游标分开；用任务类型、群、范围和分析版本保证幂等。新版分析不覆盖原消息，可比较旧版结果后再设为当前版本。

已有日报按入库时间做增量。新设计分别表达“今天发生的讨论”和“今天新发现的历史资料”，避免回填被误说成今日讨论；推送记录按任务与接收范围维护，失败可重试且不重复发送。

## 10. 数据与模块设计

沿用 SQLite 主库、现有消息表和文件接口，新增派生数据：

- `knowledge_runs`：群、时间范围、任务类型、输入水位、词表/模型/提示版本、状态、用量。
- `knowledge_items`：知识卡片、主题、价值状态、证据状态、是否固定保留与版本。
- `knowledge_evidence`：卡片与原消息、图片、URL、文件之间的关系。
- `group_summaries`：单群日期/时段摘要、来源范围与分析版本。
- `topic_glossary`：主题/群术语、别名、候选状态与来源。
- `file_assets`：内容哈希、实际大小、本地路径、校验与备份状态。
- `file_sources`：群文件 ID、原文件名、群范围、关联消息和资产。
- `knowledge_feedback`：误收、漏收、词义修正、过期或失效反馈。

原消息增加原始时间索引；知识检索索引以群范围为边界。先做 SQLite 全文检索和标签过滤，中文召回需验证分词/子串方案；语义检索作为后续可选增强，不在第一版引入独立数据库。

分析入口拆为群总结、知识提取、图片证据三个用途，共享模型连接、脱敏、预算与任务调度基础，不共享互相冲突的系统提示词。

长任务独立队列：抽取、模型分析、文件下载、备份、页面生成与发送各自记录状态。失败不推进对应成功游标，空结果必须是明确完成的分析结果。

## 11. Qt 与本地页面

复用采集页现有群列表与群资料读取，增加“知识”配置入口，每群可看到独立功能开关、匹配模式、主题、总结计划、文件策略与预算。新建群配置各功能均显示关闭，界面明确显示哪些功能已启用以及是否外发通知。

报告页增加按群和日期的总结预览；本地页面增加：

1. 群总结：群/日期筛选、话题、结论、未解决问题与来源。
2. 精选知识：主题、类型、证据状态、时间、全文搜索与收藏。
3. 文件库：用途、版本、保存状态、下载失败原因和来源。
4. 术语候选：解释建议、原上下文、确认/修改/忽略。

用户界面用“专群匹配”“泛匹配”“两者都用”“仅记录”“自动保留”“待确认”等表达，不要求用户理解游标或哈希等实现细节。管理视图可提供分析原因与任务错误详情。

## 12. 验收与调优

第一轮由 AI 提出约 300—500 个讨论片段的初始标签，再进行人工抽查并确认用于报告质量的验证样本，按群、时间、类型、价值正负例分层；重点补充当前库中不足的逆向主题样本。候选学习集合与后续验证集合分开，避免在同一数据上调分析版本并报告效果。日常运行不用逐条人工审核，人工工作集中在少量歧义、反馈和质量抽查。

必测情形：

- 无配置、旧配置升级及新增群时，新功能全部关闭，不调用新分析任务、不下载文件、不发送新通知。
- 仅开启全局或仅开启某群仍不执行；仅开启总结不会启动术语学习、文件保留、历史回放或外发。
- 保存主题、模型和预算不会自动启用功能；重启保持主动设置的状态。
- 关闭功能后，排队任务与执行前检查阻止后续下载、上传和通知，已有归档保持可查看。

- 无图片、无链接的完整排错讨论能进入知识候选。
- 只含黑话、赞美、广告或缺少结论的对话不直接入精选。
- 同一个词在绘图与其他主题群有不同解释。
- 问题和答案跨分析批次仍能关联；模型返回不存在的来源被拒绝。
- 群内查询不能带出其他群内容；私聊按授权范围选群。
- 历史回填不改变原日期、不重复推送。
- PDF/脚本能建立索引；同名不同内容保存不同版本。
- 失效下载链接、上传失败、空间不足不会显示“已保存”。
- 模型失败可恢复，后台大文件任务不阻塞实时回复。

记录每群精选准确率、标注样本召回率、重复率、证据错误率、文件保存成功率与模型用量。具体目标在样本基线产生后约定；本轮不声称现有规则已有这些质量成绩。

## 13. 建议的实施顺序

### 第一阶段：正确性与配置基础

修复总结用途混用、群资源边界、原始时间；加入默认关闭的全局、按群及功能配置和主题模板；提供手动群总结与历史预览。由用户主动选择并开启一个绘图群和一个指定逆向群试运行，开启分析后结果先在本地展示，通知仍需独立开启。

### 第二阶段：信息精选与术语

加入 AI 讨论归并、专群/泛匹配、知识卡片、证据关联、术语自动学习与歧义复核。用同一批固定历史记录比较新旧分析版本，验证后再增加自动日报。

### 第三阶段：文件持久保留

扩展文件索引类型、本地归档、内容哈希、版本与配额；再连接现有 WebDAV 副本。先保存小型工作流、脚本和资料，大型模型按群配额与手动策略处理。

### 第四阶段：检索与持续优化

加入历史知识搜索、带来源的问答、周报、过期资料提示和可选语义检索。通过人工反馈调整群规则，保留变更对照和回滚能力。

## 14. 额外建议与待确定事项

建议优先加入“问过但未解决的问题追踪”：同群后续出现答案时补全知识卡，而非重复发布新条目。对软件版本、工作流和工具记录适用版本，保留纠错与争议；比只增加摘要长度更有长期价值。

增加“为什么收录”的简短解释与“一键误收/漏收/误解术语”，让使用者能修正规则。数据多的群不能垄断预算和精选，配额与统计按群提供。

建立每群每日期的采集覆盖状态；只有实际知道存在消息缺口时标记缺口，无法确认完整性时注明“基于已记录消息”，避免用零消息解释群没有活动。

待开发前确定：试点群、逆向主题的准确含义与偏好资源、文件存储目录与容量、第一批自动保留类型、通知目的地、可接受的每日模型预算。匹配阈值不需要用户先猜，开发后用标注样本校准。
