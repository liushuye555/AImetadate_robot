# 群知识第2、3、4、5项优化

四项扩展都默认关闭。全局、具体群和对应子功能必须显式开启；`defaults` 中的开启状态不能代替群内确认。正式配置未自动启用新能力。

## 2. 模型故障切换与分级处理

原主模型与备用连接继续复用已有凭据。逐群可选择初筛连接及型号，并单独开启复核。复核读取原消息与初筛结果，再接受相同的来源编号、文件关联与证据校验；复核失败不会作为完成结果，也不会自动保存高价值原件。已完成初筛可复用，重试不重复支付初筛用量。

主动开启故障切换后，失败次数及冷却状态保存在独立的模型健康数据库中，冷却期间跳过不可用连接；冷却后只允许一个恢复探测。每个实际模型调用分别预留本群用量预算，跳过的调用不收费。模型健康状态不保存密钥或完整地址。

## 3. 文件内容预览与真实接口验证

文件保留与内容预览是独立开关。预览最多3个文件，每个最多256 KiB、6000字符；总下载量最多1 MiB。支持文本、JSON工作流、ZIP的小文本成员与PDF前3页。不解压到文件系统、不执行脚本或工作流。预览原件存入临时目录并清理；长期原件仍需满足高价值归档策略、文件类型、容量与开关检查。

PDF解析使用项目固定依赖pypdf。带凭据的文本脱敏后才进入AI输入。文件过大、类型不支持或URL失效会形成明确的预览状态，不把文件名当作内容证据。

## 4. Qt逐群配置

采集页增加群知识配置。可选当前群、设置专群/泛匹配/兼顾模式与主题，并独立控制总结、提取、术语、文件、历史、反馈等功能。模型切换、复核与预览也要逐群勾选。

新增群和扫描群列表不自动启用知识功能。删除知识群配置会写入关闭状态，防止配置深度合并后旧开关继续生效。已有未知配置项与其他群保持保留。

## 5. 纠错、方案与历史对比

本地反馈支持误收、漏收、术语理解错误、过时和确认有效。反馈必须关联本群现有知识条目或原始消息编号，跨群来源会被拒绝。网页提交需要本地页面专用令牌；正式功能关闭后立即拒绝写入。

在主动开启反馈优化后，AI依据同群纠错、知识条目及对应原消息提出主题与分析说明调整。方案保存在派生数据库中，生成不会修改配置。只有显式应用方案才更新本群主题和分析说明，并递增`analysis_revision`；方案不能更改权限、预算、功能开关或群范围。原配置已变化时拒绝应用旧方案。

历史对比为同一份消息、相同上下文分别运行原策略和候选策略，不写实时知识条目、不推进实时游标。报告保存样本指纹、原始编号、前后条目和人工反馈命中数。条目数量变化不等于准确率提高；需要人工标签判断漏收与误收变化。

命令示例（把123换成已主动开启的群，编号使用本地数据库编号）：

```powershell
uv run python -m qq_onebot_whitelist.knowledge_feedback --group 123 feedback --kind missed --message-db-id 100 --notes "这是有用的节点排错步骤"
uv run python -m qq_onebot_whitelist.knowledge_feedback --group 123 propose
uv run python -m qq_onebot_whitelist.knowledge_feedback --group 123 proposals
uv run python -m qq_onebot_whitelist.knowledge_feedback --group 123 compare --proposal-id 1 --after-id 0 --limit 30
uv run python -m qq_onebot_whitelist.knowledge_feedback --group 123 apply --proposal-id 1
```

建议先选一个绘图群与一个其他主题群做小样本，标注确认有效、误收和漏收，再决定是否应用方案。先观察初筛与复核的额外用量和实际纠错收益，再扩大开启范围。

## 验证记录

真实接口验证使用临时启用配置，正式配置未修改。历史文件样本获取URL失败后，只读扫描同一群当前文件列表，找到209079字节的ZIP；使用列表中的busid取得下载地址。归档成功，SHA256与实际内容一致；ZIP文本预览成功并明确标记截断。重复归档返回相同哈希和路径。全部原件位于临时目录，验证后清理；摘要保存在本地忽略目录，不包含下载URL、群号、文件名或内容。

实际验证还修复了OneBot `/UUID` 文件ID被旧校验误判为路径的问题，任意路径仍拒绝；补存busid供预览、保留和失败重试刷新地址。

Python回归覆盖模型失败/预算/缓存/并发、文件预览和安全边界、反馈来源与令牌、候选方案字段限制、固定历史样本与实时结果隔离。Qt离线测试覆盖新增群默认关闭、各群独立、未知字段保存、取消不写配置、扫描不启用、移除关闭以及模型提供方保存。

历史反馈流程已开发并通过隔离测试。实际群消息上的准确率改善仍需人工纠错标签；目前没有把模型自评或条目数量增加作为质量提升证据。独立复核发现Qt字段`provider`与后端`primary_provider`不一致，已统一并加回归用例；复核代理后续受到账号用量限制，剩余边界由主代理检查与测试验证。
