# 群知识第一版：开发与历史验证

日期：2026-10-13。

## 本轮完成

- 独立知识模块，默认关闭；全局、群及对应子功能均需显式开启，默认值不会开启新群。
- AI 群总结、专群/泛匹配知识提取、群内术语候选及有证据支持的词义启用。
- 日期总结按原始发送时间分批处理，显示实际覆盖范围；日报/周报计划需单独开启，结果在本地。
- 实时增量与历史回放使用独立进度，支持续跑；运行参数调整不丢弃实时积压。
- 模型输出采用结构化 JSON，核验同群原消息与文件证据；失败或截断不推进进度。
- 按群每日用量预算、请求前预留、完成缓存，以及现有备用模型回退。失败请求采用保守用量预留，不把未知费用当成零。
- 高价值文件本地保留、大小与配额限制、内容哈希、真实文件校验、失败轮转重试与缺失本体恢复。
- 文件 review 模式保留待确认记录，需主动指定文件保存；术语人工纠正优先于 AI 后续解释。
- 本地知识报告支持按群筛选、文本搜索、术语状态、文件状态和原消息证据展开。
- Qt 配置桥接增加默认关闭的总开关及基础参数；逐群功能选择目前通过 YAML 配置。

新结果存于 `data/knowledge.db`，文件存于 `data/knowledge-files/<群号>/`，报告为 `data/view/knowledge.html`。原 `bot.db` 不进行知识模块迁移，现有功能不因新默认值改变。

操作说明见 `docs/群知识功能使用说明.md`。

## 历史经验驱动的实际优化

1. 纠正“最近总结”调用图片证据提示词的问题；通用总结现在有独立用途，图片分析保留原来的参数提取提示词。
2. 群内“资源/文件”查询在数据库层先按本群过滤再限制数量，避免返回其他群资料。
3. 新总结与历史分析使用原始发送时间；不把刚回填的旧消息误当成今天讨论。
4. AI 分析使用引用和跨批次辅助上下文，短句与无 URL 的文字也能成为候选。
5. AI 未解决/存在分歧的条目强制为候选，不因模型给出 high 就作为精选。
6. 历史候选携带证据状态进入后续上下文，不能当作已验证结论继续推导。

以上是已经落地的代码行为。还没有对全部历史进行人工标注，也没有完成定量的精准率、召回率评估。

## 真实历史抽样

从两个主要群各选择一个技术讨论窗口，复制到独立验证库并匿名化群别。原消息编号保留以便核对证据；第一组另补入一条被引用记录。

| 项目 | 结果 |
| --- | ---: |
| 验证消息 | 141 条，分别为 71 和 70 条 |
| 成功分析批次 | 4 |
| 成功请求返回的 token 用量 | 19,329，不包含未知费用的失败请求 |
| 知识候选 | 3 |
| 经本轮复核后认定为精选的条目 | 0 |
| 术语解释 | 11 |
| 达到本群自动使用条件的词义 | 2，其余 9 项为候选 |

三条知识线索分别涉及：

- 画风 LoRA 的打标取舍，原讨论没有明确结论。
- Illustrious 对特定尾部形态的生成能力，原讨论是疑问，没有验证答案。
- 显卡供电线的群友说法，没有负载测试或其他验证资料。

这些内容保留为待确认线索，不能作为经过验证的技术建议。术语达到自动使用条件，也仅表示有多个不同上下文支持，并不等同于外部权威验证。

本轮发现并处理的真实模型问题：

- 当前首选模型接口返回 HTTP 错误；现有 DeepSeek 备用配置完成了实际分析。新模块加入同样的备用模型机制。
- 第二组输出被截断，最初两次被拒绝，没有写入成功结果或推进历史进度；将响应额度调整为 6,000 token 后完成。请求仍受群每日预算约束。
- 一个未解决问题曾被模型标为 high，现加入结构化校验降为 candidate，并在验证报告中纠正等级。
- 一段输出附带了原文没有的条件推断；收紧提示词禁止补写无来源解决建议。该提示词改进尚未用独立标注集评估，不能宣称已经消除此类错误。

抽样是围绕技术讨论选取的窗口，不是随机质量样本，也没有覆盖专门的逆向群。因此不能据此给出整体识别准确率、逆向领域效果或全部历史提炼完成度。
