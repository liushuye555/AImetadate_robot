# 资料分类与讨论归档

资料同时保留三个维度，避免把“未解决”当成可复用结论：

- 处理队列：知识、待跟进、归档。问题缺少答案时保留求助线索；归档只退出默认展示和普通 AI 上下文，原文、证据与讨论历史保留。
- 主题：逆向与工具、模型使用与接入、额度计费与订阅、编程开发与部署、账号登录与风控、资料与工具资源、服务状态与公告、其他／待分类。每条可有多个主题，话题汇总历次记录的主题。
- 资料类型：可复用知识、待解决问题、资源线索、时效信息。术语继续独立显示，不计入知识数量。

知识页默认显示“知识”；选择“待跟进”可查看未解决问题，选择“全部”可检索所有内容。主题和资料类型可组合筛选。AI 分类是整理标注，不会把群友说法升级为已验证结论。

## 自动过期与开启方式

管理器“采集 → 群知识 → 编辑具体群组”中，主动勾选“自动归档过期讨论”，并保存配置；同时需要全局群知识及本群总开关开启。仅设置默认天数不会启用任何群。四类天数范围均为 1—3650：

| 内容 | 默认保留期 |
| --- | ---: |
| 简短、缺少条件的求助 | 3 天 |
| 带环境、错误、操作或反馈的问题 | 14 天 |
| 时效信息 | 3 天 |
| 未验证资源线索 | 30 天 |

可复用知识长期保留。已验证解决的问题进入知识队列，不再按未解决问题过期。归档不改写解决状态，也不删除文件或聊天原始记录。

计时采用原消息时间，不采用分析时间或数据库更新时间。同一讨论的重复提问、转述和未知进展不会延长保留期，也不能通过改成“详细问题”或“知识”延长时效。只有原文精确引文支持的新条件、排查步骤或结果，才推进最后有效进展；使用该引文本身的消息时间，避免较晚重复消息混入同条整理结果后续期。无可靠原始时间时不自动过期。

AI 每次构建上下文时重新判断归档；静态报告在重新生成时刷新归档状态。自动归档的旧讨论被新消息明确引用时，可供 AI 复核关联，但重复内容仍不续期。人工归档的讨论不会自动恢复。

## 人工归档与保留

可通过本地命令调整完整话题，`active` 表示人工保留并暂停自动过期，`auto` 表示恢复按群自动策略：

```powershell
.venv/Scripts/python.exe -m qq_onebot_whitelist.knowledge archive --group 群号 --topic-id 话题编号 --state archived
.venv/Scripts/python.exe -m qq_onebot_whitelist.knowledge archive --group 群号 --topic-id 话题编号 --state active
.venv/Scripts/python.exe -m qq_onebot_whitelist.knowledge archive --group 群号 --topic-id 话题编号 --state auto
```

未关联话题的独立条目可用 `--item-key`。已属于话题的条目会提示使用完整话题编号，避免表面归档了条目、同一内容仍从话题进入上下文。人工动作只允许操作指定群中的既有记录。

## 指代不清的封禁讨论

这次核对的原文先询问“你们说用在GPT身上会怎么样？”，随后说明“我的意思是封号”，另有人建议“蹬中转的”，之后一名群友称“我的已经封了”。最后一句所引用的消息 `184542957` 未在本地采集库中找到。

这些证据不能确定所用工具、提示词或服务，也不能确定被封账号的平台和账号类型；“蹬中转的”只是一条建议，不构成封禁原因证据。整理结果应作为对象待确认的问题，分别显示已知内容和缺少信息，不建立工具导致封禁的因果关系。报告里的“成员15”等是批次内匿名代号，不是永久成员编号。

新分析提示要求输出主题、有效进展引文和指代对象证据。提供组织标注但缺少有效对象证据时，会保守标为对象待确认的问题。完全缺少组织标注的旧格式仍兼容读取与校验，保留原有候选及质量规则；这一兼容路径不提供自动确认对象的保证。
